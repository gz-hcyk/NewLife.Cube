# NewLife.Cube 安全审计报告

> 版本：v1.0 | 日期：2026-09-23  
> 审计范围：分支 `cursor/mfa-two-factor-7061`（相对 `dev`）及关联认证链路  
> 审计角色：Web 安全专家审查（静态代码分析 + 逻辑推演 + 针对性测试设计）  
> 标准参考：OWASP ASVS 4.0（身份鉴别 V2 / 会话 V3 / 访问控制 V4）、等保身份鉴别增强、仓库 `Doc/安全与审计.md`

---

## 1. 执行摘要

| 维度 | 结论 |
|------|------|
| 总体风险 | **高**：MFA 新增能力方向正确，但存在可导致「第二因子形同虚设」的实现缺陷 |
| 最严重问题 | 登录挑战态 `mfaToken` 可被滥用于 **重置 TOTP 并完成登录** |
| 策略空洞 | `EnableMfa` / `MfaRequired` **仅作用于密码登录**，短信/邮件/SSO 可单因子拿会话 |
| 防爆破 | MFA 校验 **未**与 `MaxLoginError` 联动（与架构文档不一致） |
| 测试覆盖 | 已有 TOTP/门闸单测 8 项通过；**缺少**安全负面用例（绕过、限速、重绑鉴权） |

**建议**：在合并前至少修复 Critical×1 + High（限速、挑战令牌绑定边界）；策略绕过需产品确认「MFA 是否覆盖全部登录入口」。

### 1.1 发现统计

| 严重度 | 数量 | 说明 |
|--------|------|------|
| Critical | 1 | 挑战令牌劫持 TOTP |
| High | 4 | MFA 无限速、默认加密密钥、SMS/Mail/SSO 绕过策略、已登录无确认重绑 |
| Medium | 6 | CSRF、通道启停无二次确认、恢复码并发、明文回退、外部 QR、审计泄露 |
| Low / Info | 若干 | 常量时间比较、备份码盐、死按钮、文档不一致等 |

## 2. 审计范围与方法

### 2.1 范围

- **核心**：`MfaService`、`Totp`、`UserService` 密码门闸、MVC/WebAPI `UserController` MFA 接口、`Mfa*.cshtml`
- **关联**：短信/邮件验证码登录、SSO `OnLogin`、JWT/Cookie 会话、`CubeSetting` 安全配置

### 2.2 方法

1. 差分审查（`dev` → 当前分支）  
2. 威胁建模（STRIDE 侧重伪造身份 / 提升权限 / 信息泄露）  
3. 对照自有架构文档（`Doc/MFA二步验证/架构设计.md`）与 ASVS 条目  
4. 逻辑 PoC 草图（**不含**可直接打生产的利用载荷）

## 3. 详细发现

### C-1 【Critical】挑战态 `mfaToken` 可重置 TOTP 并绕过原第二因子

| 项 | 内容 |
|----|------|
| 位置 | `UserController.ResolveMfaUser` / `MfaTotpStart` / `MfaTotpConfirm`；`MfaService.ResolveTokenUser`、`ConfirmTotpSetup` |
| 风险 | 攻击者只需「账号密码正确」拿到挑战令牌，即可在**未验证原 Authenticator** 的情况下换绑 TOTP，再用新码 `VerifyMfa` 登录；亦可造成受害者原验证器失效（DoS/接管） |
| 根因 | `MfaTotpStart/Confirm` 为 `[AllowAnonymous]` 且接受任意有效 `mfaToken`；`requireSetup` 默认 `false`；确认绑定时不校验旧因子 |
| 复现步骤（草图） | ① 密码登录得 `code=1002`+`mfaToken` ② `POST MfaTotpStart` ③ 攻击者 App 扫码/录密钥 ④ `POST MfaTotpConfirm` ⑤ `POST VerifyMfa` |
| 修复 | 挑战令牌**禁止**进入绑定 API；仅 `IsSetup=true` 或已登录+二次确认可绑；已绑定重绑必须 `EnsureConfirm` |

### H-1 【High】MFA 校验无速率限制 / 失败不锁定

| 项 | 内容 |
|----|------|
| 位置 | `MfaService.VerifyChallenge`；`UserService.VerifyMfa` |
| 风险 | `mfaToken` 默认 300s 内可无限试错；6 位 TOTP（±1 窗口）与短 SMS OTP 可被在线猜解；架构要求「失败计入 MaxLoginError」未实现 |
| 修复 | 按 token/user/IP 累计失败，达阈作废挑战并锁定；常量时间比较 |

### H-2 【High】TOTP 密钥加密依赖可预测默认材料

| 项 | 内容 |
|----|------|
| 位置 | `MfaService.DeriveKey` |
| 风险 | `JwtSecret` 为空时使用硬编码 `"NewLife.Cube.Mfa.DefaultKey"`；库泄露后可批量解出 TOTP |
| 修复 | 无密钥拒绝启用 MFA；独立 `MfaProtectionKey`；禁止默认密钥 |

### H-3 【High】`EnableMfa`/`MfaRequired` 不覆盖短信、邮件、SSO 登录

| 项 | 内容 |
|----|------|
| 位置 | `LoginBySms` / `LoginByMail` 直接 `CompleteLogin`；SSO `SaveCookie` |
| 风险 | 「强制 MFA」策略可被一因子通道绕过 |
| 修复 | 全登录路径统一 MFA 评估；或产品明确缩小保证范围并在 UI 强提示 |

### H-4 【High】已登录用户重绑 TOTP 无需证明持有旧因子

| 项 | 内容 |
|----|------|
| 位置 | 无 `mfaToken` 时的 `MfaTotpStart/Confirm` |
| 风险 | 会话劫持后可静默换绑，实现持久接管 |
| 修复 | `TotpConfirmed` 为真时强制旧 TOTP/密码/恢复码确认 |

### M-1 【Medium】外部 QR 服务接收完整 `otpauth`（含 secret）

| 项 | 内容 |
|----|------|
| 位置 | `Mfa.cshtml`、`MfaSetup.cshtml` → `api.qrserver.com` |
| 风险 | TOTP 密钥离开受信边界（第三方日志/缓存/供应链） |
| 修复 | 本地/前端离线生成二维码 |

### M-2 【Medium】敏感 MFA POST 缺少 Anti-Forgery

| 项 | 内容 |
|----|------|
| 位置 | `MfaChannel` / `MfaDisable` / `MfaTotpConfirm` 等 |
| 风险 | 同站请求伪造可关闭 MFA、换绑、启停弱通道（Cookie 会话场景） |
| 修复 | `[ValidateAntiForgeryToken]` + SameSite Cookie |

### M-3 【Medium】短信/邮件通道启停无需第二因子；静默生成恢复码

| 项 | 内容 |
|----|------|
| 位置 | `MfaService.SetChannel` |
| 风险 | 会话窃取可打开较弱 SMS 因子；恢复码哈希生成但用户未见明文 |
| 修复 | 启停需确认；恢复码必须一次展示 |

### M-4 【Medium】恢复码消费存在并发双花窗口

| 项 | 内容 |
|----|------|
| 位置 | `ConsumeBackupCode` 读改写无锁 |
| 修复 | 乐观锁 / 条件更新 / 短时互斥 |

### M-5 【Medium】`UnprotectSecret` 解密失败回退明文

| 项 | 内容 |
|----|------|
| 位置 | `MfaService.UnprotectSecret` |
| 风险 | 掩盖配置错误；扩大泄露影响面 |
| 修复 | 生产禁止明文回退；失败强制重绑 |

### M-6 【Medium】密码风控与 MFA 风控脱节

| 项 | 内容 |
|----|------|
| 位置 | 密码成功即清零错误计数；MFA 失败不累计 |
| 修复 | MFA 失败写入共享或独立计数器 |

### L / Info（节选）

| ID | 说明 | 建议 |
|----|------|------|
| L-1 | TOTP/`==` 非常量时间比较 | 固定时间比较 |
| L-2 | 恢复码 SHA256 无 per-user 盐 | HMAC 或加盐 |
| L-3 | `IsActive` 对空数组 `"[]"` 可能仍为真 | 用剩余数量判断 |
| L-4 | 解绑按钮无对应 Action | 补齐或移除 |
| L-5 | MFA 短信 Action 复用 `login` | 独立 `mfa` 便于审计 |
| L-6 | `VerifyMfa` 失败日志可能写入完整 `mfaToken` | 仅记哈希前缀 |
| I-1 | 密码步短暂 `SaveCookie` 后 `Logout` | 更优：MFA 前不写 Cookie |
| I-2 | 挑战令牌 `Rand.NextString(32)` 熵基本足够 | 保持 CSPRNG |

## 4. OWASP ASVS 对照（摘要）

| 条目 | 要求 | 现状 |
|------|------|------|
| V2.2 | 防暴力破解 | MFA 校验未限速 → **不满足** |
| V2.8 | 多因子应用于敏感操作/登录 | 仅密码路径 → **部分满足** |
| V2.9 | 恢复码安全 | 哈希存储较好；无限速/并发 → **部分满足** |
| V2.10 | 密钥保管 | 默认密钥/外发 QR → **不满足** |
| V3 | 会话 | 挑战前 Logout 较好；CSRF/SameSite 待加强 |
| V4 | 访问控制 / CSRF | MFA 状态变更缺 Anti-Forgery → **部分满足** |

## 5. 已验证相对稳健的设计

1. 密码校验成功后 `Logout` 再发挑战，避免「未过 MFA 即持会话」。  
2. 校验成功消费 `mfaToken`；SMS/Mail **发送**侧有 IP/60s 频控。  
3. TOTP 160-bit、RFC 6238；恢复码不明文落库。  
4. 绑定/校验失败有部分审计日志。  
5. 单元测试覆盖 TOTP 正确性与「已绑定需挑战」门闸（**未**覆盖本报告攻击路径）。

## 7. 修复优先级与验收

### P0（合并前必须）

1. 挑战令牌与 TOTP 绑定 API 隔离；重绑二次确认（C-1 / H-4）  
2. MFA 校验失败限速与锁定（H-1）  
3. 去掉默认加密密钥或强制配置（H-2）  
4. 本地 QR，禁用第三方 otpauth 外发（M-1）

### P1（短期内）

5. 明确并实现「全登录路径 MFA」或缩小产品承诺（H-3）  
6. Anti-Forgery + 通道启停二次确认（M-2 / M-3）  
7. 恢复码并发安全、去掉明文回退（M-4 / M-5）

### 验收标准

- ST-01～ST-03、ST-06、ST-07 自动化通过  
- 威胁模型更新：`Doc/MFA二步验证/架构设计.md` 与实现一致  
- 无 Critical / 未缓解 High 进入发布说明

---

## 8. 结论

审计发现 MFA 实现存在可导致第二因子失效的 Critical 问题及多项 High 风险。**P0 项已在同分支即时加固**（见 §9），回归测试 ST-01/ST-03/重绑确认已纳入。剩余 **H-3（短信/邮件/SSO 绕过 MFA 策略）** 需产品确认覆盖范围后再改；CSRF 等列入 P1。

合并前建议：确认 H-3 产品决策，并完成 ST-01～ST-03、ST-07 验收。
