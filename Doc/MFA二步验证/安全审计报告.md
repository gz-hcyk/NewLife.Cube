## 2. 审计范围、资产与方法

### 2.1 资产与攻击面

| 资产 | 说明 |
|------|------|
| 身份 | 密码 / 短信 / 邮件 / SSO(OAuth) / MFA 挑战与强制绑定 |
| 会话 | Cookie、`ManageProvider` Current、JWT（front-end token） |
| 机密 | TOTP Secret（AES）、恢复码哈希、`JwtSecret`、短信/邮件 OTP |
| 个人信息 | 手机、邮箱、DisplayName、登录 IP、审计日志 |
| 配置 | `EnableMfa` / `MfaRequired` / `MfaTokenExpire` / `MaxLoginError` |

### 2.2 方法矩阵

| 手段 | 做法 | 结果形态 |
|------|------|----------|
| **静态分析（白盒）** | 通读 `MfaService`/`Totp`/`UserService`/`SsoProvider`/`UserController`/`Mfa*.cshtml`、Setting、实体 | 数据流与控制流缺陷清单 |
| **差分审查** | `dev` → 本分支 MFA/SSO 变更 | 回归安全债与修复有效性 |
| **威胁建模** | STRIDE：伪造、篡改、否认、信息泄露、拒绝服务、提权 | 攻击树与优先级 |
| **灰盒逻辑渗透** | 推演「已知密码 / 持有短信 / 持 mfaToken / CSRF / XSS」路径 | 概念级复现步骤（无生产 exploit 载荷） |
| **注入 / XSS 专项** | 审查 Razor/`Html.Raw`/JS 字符串拼接、查询参数进脚本 | Setup 页 XSS、恢复码 Raw |
| **跨站 / CSRF** | 检查 AntiForgery、SameSite、敏感 POST | 通道启停/Disable 面 |
| **黑盒用例设计** | 见 §6 测试矩阵（可纳入 CI / 手工渗透） | 验收用例 |
| **个人信息 / 数据保护** | 脱敏、最小化、密钥分离、日志留存 | PIPL/35273 对照 |

**不在本期**：全量依赖 CVE SCA、生产环境破坏性爆破、主题皮肤全站 XSS 爬取、物理与社工。

## 3. 详细发现

### C-1 【Critical】短信 / 邮箱验证码登录绕过 MFA — **已关闭（v2.1）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：`LoginBySms` / `LoginByMail` 与密码共用 `FinishLoginOrMfa` → `EvaluateAfterLogin` |
| 分类 | 认证绕过 / 策略失效（系统安全） |
| 原位置 | `UserService.LoginBySms` / `LoginByMail` 曾直接 `CompleteLogin` |
| 验证 | 回归测试 `ST-04_EvaluateAfterLogin_短信邮件登录与密码SSO共用判定`；架构文档已同步 |

---

### H-1 【High】`MfaChannel` 无第二因子确认 + 缺 CSRF 防护 — **已关闭（v2.2）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：`SetChannel` 强制 `EnsureConfirm`；MVC 敏感 POST 加 `[ValidateAntiForgeryToken]`；视图携带 token；新恢复码一次返回 |

### H-2 【High】SSO 将 `mfaToken` 置于 URL 查询串 — **已关闭（v2.2）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：`MfaSession` HttpOnly Cookie `Cube.MfaToken`；跳转仅 `/Admin/User/MfaChallenge|MfaSetup`；兼容查询串回读 |

---

### H-3 【High】`MfaSetup.cshtml` 将 `returnUrl` 直接嵌入 JavaScript（XSS） — **已关闭（v2.1）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：`JsonSerializer.Serialize` 后 `@Html.Raw(returnUrlJson)` 注入 JS 字符串字面量 |
| 原位置 | `MfaSetup.cshtml` 曾 `r: '@returnUrl'` |

---

### H-4 【High】`Logout` 开放重定向 — **已关闭（v2.1）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：`Url.IsLocalUrl(returnUrl)`；SSO 注销链路仅传递本地 `r` |
| 原位置 | `UserController.Logout` 曾无条件 `Redirect(returnUrl)` |

---

### H-5 【High】启用 MFA 后存量会话无再校验 — **已关闭（v2.2）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：`CompleteLogin`/SSO 写 `Cube.MfaOk` 会话戳；`TryLogin` 对已绑定 MFA 用户校验戳，缺失则 Logout |

### H-6 【High】恢复码 SHA256 无盐，熵约 40 bit — **已关闭（v2.2）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：16 位码 + `v2:salt:hmac`；兼容旧无盐 SHA256；单测覆盖一次消费 |

---

### M-1 【Medium】SSO 在 MFA 完成前已更新 LastLogin / Online — **已关闭（v2.3）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：`Logins`/`LastLogin`/`Online` 移至 MFA 门闸之后再落库 |

### M-2 【Medium】`forceBind`（OAuth Bind）跳过 MFA — **已关闭（v2.3）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：`EnableMfa` 下 Bind 要求当前会话持有 `Cube.MfaOk`；否则拒绝 |

### M-3 【Medium】`JwtSecret` 弱默认且与 TOTP 保护密钥耦合 — **已关闭（v2.3）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：独立 `MfaProtectionKey`（OnLoaded 自动 32 字符）；`DeriveKey` 优先保护密钥；JwtSecret 默认加长至 32 |

### M-4 【Medium】SMS/Mail 挑战码发送面 — **已关闭（v2.3）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：用户日限额 20；保留 IP/60s 频控；`MaxLoginError` 默认强制 >0（既有 OnLoaded） |

### M-5 【Medium】密码登录先写 Cookie 再 Logout — **已关闭（v2.3）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：本地账密走 `LoginCore`（不写 Cookie）；OAuth 密码模式仍走 `Login` + MFA 后 Logout |

### M-6 【Medium】MFA 成功后未再生会话 — **已关闭（v2.3）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：`CompleteLogin` 清空服务端 Session 字典后再 `SaveCookie`/写戳 |

## 7. 已验证相对稳健的设计

1. 密码登录需挑战/绑定时 `Logout` 后再发令牌，避免「未过 MFA 持完整会话」。  
2. SSO：`TryPrepareMfaRedirect` + Controller 提前 Redirect，不记在线、不发 front-end token。  
3. 挑战令牌与 setup 令牌用途隔离；校验成功消费令牌。  
4. TOTP：CSPRNG 160-bit、RFC 6238；落库 AES；状态页手机/邮箱脱敏。  
5. 恢复码不明文落库；Disable/重建恢复码需二次确认。  
6. Cube 与 CubeNC 登录/`MfaService` 链接编译，两端 SSO 门闸对齐。  
7. MFA 成功路径与 Logout 均 `Url.IsLocalUrl`。  
8. 短信/邮件第一因子登录经 `FinishLoginOrMfa`，与密码/SSO 策略一致。

## 9. 结论

**v2.3**：审计所列 Critical / High / Medium 均已关闭。全登录入口 MFA 门闸、Cookie 令牌与会话戳、通道确认与 AntiForgery、独立保护密钥、LoginCore 免 MFA 前写 Cookie、SSO 审计时序与 Bind 约束已落地。

**残留 Low**：TOTP 常量时间比较、恢复码并发双花窗口——不影响主验收。WebApi 管理面不对称 **已关闭（对称 API）**。
