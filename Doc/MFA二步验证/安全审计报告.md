## 3. 详细发现

### C-1 【Critical】短信 / 邮箱验证码登录绕过 MFA — **已关闭（v2.1）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：`LoginBySms` / `LoginByMail` 与密码共用 `FinishLoginOrMfa` → `EvaluateAfterLogin` |
| 分类 | 认证绕过 / 策略失效（系统安全） |
| 原位置 | `UserService.LoginBySms` / `LoginByMail` 曾直接 `CompleteLogin` |
| 验证 | 回归测试 `ST-04_EvaluateAfterLogin_短信邮件登录与密码SSO共用判定`；架构文档已同步 |

---

### H-1 【High】`MfaChannel` 无第二因子确认 + 缺 CSRF 防护

| 项 | 内容 |
|----|------|
| 分类 | 提权降级 / CSRF（系统安全） |
| 位置 | `UserController.MfaChannel`；`MfaService.SetChannel`（约 357–392 行）；`Mfa.cshtml` 裸 `$.ajax` POST |
| 攻击场景 | 已登录会话被 XSS/CSRF：关闭短信/邮件通道或关至零因子使 `Enable=false`，静默拆除 MFA。对比 `Disable`/`RegenerateBackupCodes` 已有 `EnsureConfirm` |
| 修复 | 启停通道、关 MFA、换绑统一二次确认；`[ValidateAntiForgeryToken]` 或自定义头 + SameSite；禁止无确认降至零因子 |
| 个人信息 | 攻击者可持续访问账号下业务与个人数据 |

---

### H-2 【High】SSO 将 `mfaToken` 置于 URL 查询串

| 项 | 内容 |
|----|------|
| 分类 | 会话/令牌泄露（系统安全 + 个人信息） |
| 位置 | `SsoProvider.TryPrepareMfaRedirect`（约 240–247 行）；`SsoController` 再附 `r=` |
| 攻击场景 | 浏览器历史、反向代理/WAF 访问日志、Referer（外链资源）泄露令牌；有效期内可完成挑战或强制绑定并登录 |
| 说明 | `Rand.NextString(32)` **抗猜测**，**不抗泄露** |
| 修复 | HttpOnly Cookie / TempData / 一次性短 ticket；缩短 TTL；禁止日志打印完整 token |

---

### H-3 【High】`MfaSetup.cshtml` 将 `returnUrl` 直接嵌入 JavaScript（XSS） — **已关闭（v2.1）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：`JsonSerializer.Serialize` 后 `@Html.Raw(returnUrlJson)` 注入 JS 字符串字面量 |
| 原位置 | `MfaSetup.cshtml` 曾 `r: '@returnUrl'` |

---

### H-4 【High】`Logout` 开放重定向 — **已关闭（v2.1）**

| 项 | 内容 |
|----|------|
| 状态 | **已修复**：`Url.IsLocalUrl(returnUrl)`；SSO 注销链路仅传递本地 `r` |
| 原位置 | `UserController.Logout` 曾无条件 `Redirect(returnUrl)` |

---

### H-5 【High】启用 MFA 后存量会话无再校验

| 项 | 内容 |
|----|------|
| 分类 | 策略时效 / 访问控制 |
| 位置 | 门闸仅在密码登录与 SSO `OnLogin`；中间件无「MFA 已满足」声明 |
| 攻击场景 | 开启 `EnableMfa`/`MfaRequired` 前已登录的 Cookie/JWT 持续有效直至过期 |
| 修复 | 开启全局 MFA 时批量作废会话或强制声明位；认证管道检查 MFA claim |

---

### H-6 【High】恢复码 SHA256 无盐，熵约 40 bit

| 项 | 内容 |
|----|------|
| 分类 | 数据保护 / 离线破解 |
| 位置 | `GenerateBackupCodes`（8 位字母数字）+ `HashCode` SHA256 无 per-code 盐（约 476–508 行） |
| 攻击场景 | `UserMfa.BackupCodes` 库表泄露后 GPU 穷举，恢复码可直接过 MFA |
| 修复 | Argon2id/bcrypt + 随机盐；提高码熵（≥128 bit 等效）；限制失败与剩余次数 |
| 合规 | GB/T 35273 存储保护；ASVS V2.9 部分不满足 |

---

### M-1 【Medium】SSO 在 MFA 完成前已更新 LastLogin / Online

| 项 | 内容 |
|----|------|
| 位置 | `SsoProvider.OnLogin` 约 181–190 行先落库，再 `TryPrepareMfaRedirect` |
| 影响 | 审计与在线状态「已登录」失真；**Cookie 层面** MFA 前会 Logout，非直接会话绕过 |
| 修复 | 登录计数/在线状态挪到 MFA 成功（对齐 `CompleteLogin`） |

---

### M-2 【Medium】`forceBind`（OAuth Bind）跳过 MFA

| 项 | 内容 |
|----|------|
| 位置 | `OnLogin` `if (!forceBind && ...)`（约 197–202 行） |
| 影响 | 若会话来自 C-1 短信登录，可再绑第三方形成持久无 MFA 入口（链式放大） |
| 修复 | Bind 要求已 MFA 会话；文档明确约束 |

---

### M-3 【Medium】`JwtSecret` 弱默认且与 TOTP 保护密钥耦合

| 项 | 内容 |
|----|------|
| 位置 | `Setting.OnLoaded` 可能生成 `HS256:{Rand.NextString(16)}`；`DeriveKey` SHA256(`JwtSecret`) |
| 影响 | 配置泄露可解 TOTP；轮换 JWT 导致全部 TOTP 密文失效 |
| 修复 | 独立 `MfaProtectionKey`（≥256 bit）；禁止弱默认上线 |

---

### M-4 【Medium】SMS/Mail 挑战码发送面（轰炸 / 枚举）

| 项 | 内容 |
|----|------|
| 位置 | `GuardSendRate`：同号 60s、同 IP 10 分钟 5 次；`MaxLoginError<=0` 时校验无限速 |
| 影响 | 费用/骚扰；弱配置下 6 位码在线猜解风险上升 |
| 修复 | 用户日限额；强制 `MaxLoginError>0`；统一错误文案 |

---

### M-5 【Medium】密码登录先 `Login`（写 Cookie）再 `Logout`

| 项 | 内容 |
|----|------|
| 位置 | `LoginByPassword` 约 168–196 行 |
| 影响 | 同请求内通常可接受；异常中间件/代理只认首个 Set-Cookie 时存在边角窗口 |
| 修复 | 密码校验用只读 Check，通过后再发挑战，避免 MFA 前写会话 |

---

### M-6 【Medium】MFA 成功后未再生会话 ID（会话固定）

| 项 | 内容 |
|----|------|
| 位置 | `CompleteLogin` 无 Session 再生 |
| 修复 | 登录/MFA 成功时 `Session.Regenerate` / 换发 Cookie |

## 7. 已验证相对稳健的设计

1. 密码登录需挑战/绑定时 `Logout` 后再发令牌，避免「未过 MFA 持完整会话」。  
2. SSO：`TryPrepareMfaRedirect` + Controller 提前 Redirect，不记在线、不发 front-end token。  
3. 挑战令牌与 setup 令牌用途隔离；校验成功消费令牌。  
4. TOTP：CSPRNG 160-bit、RFC 6238；落库 AES；状态页手机/邮箱脱敏。  
5. 恢复码不明文落库；Disable/重建恢复码需二次确认。  
6. Cube 与 CubeNC 登录/`MfaService` 链接编译，两端 SSO 门闸对齐。  
7. MFA 成功路径与 Logout 均 `Url.IsLocalUrl`。  
8. 短信/邮件第一因子登录经 `FinishLoginOrMfa`，与密码/SSO 策略一致。

## 9. 结论

本轮在 **系统安全、个人信息保护、数据保护** 三维下完成审计；产品确认后已落地 **v2.1 P0**：短信/邮件登录 MFA 门闸、Setup XSS、Logout 开放重定向。

**已加固**：挑战/绑定令牌隔离、校验限速、禁止默认密钥、本地密钥、SSO + 密码 + 短信 + 邮件统一 `EvaluateAfterLogin`。

**残留重点（P1）**：通道 CSRF/无确认降级、`mfaToken` URL 泄露、存量会话、恢复码弱哈希。
