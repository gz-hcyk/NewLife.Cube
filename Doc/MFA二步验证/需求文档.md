# MFA 二步验证需求文档

> 版本：v1.0 | 日期：2026-09-23

本文档描述 NewLife.Cube「MFA 二步验证」模块的愿景、范围与验收标准。完成状态见 [功能清单](功能清单.md)，实现方案见 [架构设计](架构设计.md)，界面见 [原型](原型/index.html)。

## 1. 背景与愿景

### 1.1 定位

为魔方后台登录增加**第二因子认证**：账号密码通过后，须再通过短信/邮件验证码或 TOTP（Authenticator）之一，方可建立会话并发放令牌。关闭 MFA 时行为与现网一致。

### 1.2 愿景

管理员可全局启停与强制；用户可自行绑定 TOTP / 短信 / 邮件，并持有恢复码；登录与 API 客户端走同一套挑战—应答协议。

## 2. 核心目标

| 编号 | 目标 | 一句话描述 |
|------|------|------------|
| AUTH-MFA | 二步验证 | 密码正确后必须过第二因子才能登录 |
| AUTH-CH | 双通道 | 支持短信/邮件 OTP 与 TOTP |
| AUTH-CFG | 可配置 | 全局开关 + 按用户启停 |
| AUTH-UX | 可管理 | 绑定/解绑/恢复码 + 登录挑战页 + 系统设置 |

## 3. 范围

### 3.1 做

- 全局：`EnableMfa`（总开关）、`MfaRequired`（强制所有用户启用至少一种第二因子）
- 按用户：启用/停用 MFA；绑定 TOTP；将已验证手机/邮箱作为 MFA 通道；生成/查看一次恢复码
- 登录：密码成功 → 若需 MFA → 返回挑战（不发 Token）→ 校验第二因子 → `CompleteLogin`
- API 与 MVC 同源协议；默认 ACE 登录主题 + 用户「安全设置」页 + `/Admin/Cube` 配置项
- 审计：绑定/解绑/挑战成功失败写入日志

### 3.2 不做

- WebAuthn / 硬件密钥
- 推送审批（Push）
- 按 IP/设备信任免二次验证（本期不做「信任此设备」）
- 改造短信/邮件作为**第一因子**无密码登录（已有能力保持不变）
- 全主题皮肤逐一定制（本期默认 ACE；其它主题可后续覆盖视图）

### 3.3 验收标准

1. **开启 MFA 且用户已绑定至少一种第二因子**：密码正确 → 必须先过第二因子 → 才能拿到会话/Token。
2. **全局关闭 `EnableMfa`**：密码登录与现网一致，无挑战页。
3. **`MfaRequired` 开启且用户未绑定任何第二因子**：密码正确后引导至绑定页（或拒绝完成登录并提示须先绑定），不得直接发 Token。
4. TOTP、短信、邮件、恢复码四条通道均可独立完成挑战（通道需已绑定/可用）。
5. 恢复码一次性消耗；用尽可重新生成（需当前 MFA 或密码确认）。

## 4. 角色与场景

| 角色 | 场景 |
|------|------|
| 系统管理员 | 在魔方设置中开关 MFA / 强制 MFA；配置短信邮件（沿用现有） |
| 普通用户 | 安全设置中绑定 TOTP、确认手机/邮箱用于 MFA、查看恢复码 |
| API 客户端 | 登录返回 `code=1002` + `mfaToken`，再调校验接口完成登录 |

## 5. 界面清单（详见图原型）

| 编号 | 界面 | 说明 |
|------|------|------|
| P1 | 登录 — 密码步 | 现有登录表单，交互不变 |
| P2 | 登录 — MFA 挑战 | 选择通道 + 输入验证码 / TOTP / 恢复码 |
| P3 | 用户 — 安全设置 | MFA 总览、绑定状态、操作入口 |
| P4 | 绑定 TOTP | 展示密钥/二维码 → 输入首码确认 → 展示恢复码 |
| P5 | 解绑 / 关闭 MFA | 需当前第二因子或密码确认 |
| P6 | 系统设置片段 | Cube 设置「用户登录」下 MFA 开关 |

## 6. 已确认决策

| 项 | 决策 |
|----|------|
| 第二因子 | 短信/邮件 + TOTP（1C） |
| 功能范围 | 全部（开关、按用户、登录挑战、绑定解绑恢复码、管理端与登录 UI） |
| UI | 全部（含登录与安全设置） |
| 验收 | 开启须过第二因子；关闭与现网一致 |
