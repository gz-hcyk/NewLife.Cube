# MFA 二步验证架构设计

> 版本：v1.0 | 日期：2026-09-23

## 1. 总体方案

在现有各第一因子登录成功 → `CompleteLogin` 之间插入统一 MFA 门闸（`EvaluateAfterLogin` / `FinishLoginOrMfa`）：

```
密码校验成功 / SSO 认证成功 / 短信验证码登录成功 / 邮箱验证码登录成功
  → EnableMfa == false？ → CompleteLogin（现网）
  → 用户无 MFA 绑定？
       → MfaRequired？ → 返回「须绑定 MFA」/ 跳转 MfaSetup（不发 Token、不建会话）
       → 否则 → CompleteLogin
  → 已绑定 → 签发短期 mfaToken → 返回 code=1002 或跳转 MfaChallenge
  → 客户端 VerifyMfa(mfaToken, method, code) → CompleteLogin

说明：SSO「绑定已有登录账号」（forceBind）不二次挑战。短信/邮件作为第一因子登录成功后，仍须过第二因子（验证码登录 ≠ 已完成 MFA）。
```

第二因子实现：

| 通道 | 数据 | 校验 |
|------|------|------|
| TOTP | `UserMfa.TotpSecret`（加密落库） | RFC 6238，窗口 ±1 |
| SMS | 用户已验证 Mobile + 现有短信服务 | `Action=mfa`，缓存键 `Mfa:Sms:{userId}` |
| Mail | 用户已验证 Mail + 现有邮件服务 | `Action=mfa`，缓存键 `Mfa:Mail:{userId}` |
| Backup | 恢复码哈希列表 | 命中即删除该码 |

## 2. 数据模型

新建 Cube 库实体 `UserMfa`（不改 XCode.Membership.User 表结构）：

| 字段 | 类型 | 说明 |
|------|------|------|
| Id | Int64 | 主键 |
| UserId | Int32 | 唯一，对应用户 |
| Enable | Boolean | 用户侧 MFA 是否启用 |
| TotpSecret | String | 加密后的 Base32 密钥，空表示未绑 |
| TotpConfirmed | Boolean | 已完成首码确认 |
| SmsEnabled | Boolean | 允许用短信作第二因子 |
| MailEnabled | Boolean | 允许用邮件作第二因子 |
| BackupCodes | String | 恢复码哈希 JSON 数组 |
| UpdateTime / CreateTime | DateTime | 常规 |

`CubeSetting` 新增（分类「用户登录」）：

| 属性 | 默认 | 说明 |
|------|------|------|
| EnableMfa | false | 总开关 |
| MfaRequired | false | 强制绑定 |
| MfaTokenExpire | 300 | 挑战令牌秒数 |
| MfaIssuer | 应用名 | TOTP otpauth issuer |

## 3. API 协议

### 3.1 登录（扩展）

密码成功且需 MFA 时（MVC JSON / WebAPI）：

```json
{
  "code": 1002,
  "msg": "需要二步验证",
  "data": {
    "mfaToken": "...",
    "expireIn": 300,
    "methods": ["totp", "sms", "mail", "backup"]
  }
}
```

MVC 表单提交：Redirect 至挑战页并携带一次性 `mfaToken`（Cookie 或 Query，优先短时 Cookie）。

### 3.2 新接口

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/Admin/User/VerifyMfa` | 匿名 + mfaToken | 完成第二因子 |
| POST | `/Admin/User/SendMfaCode` | 匿名 + mfaToken | 发送 sms/mail 挑战码 |
| GET | `/Admin/User/Mfa` | 登录用户 | 安全设置页 / 状态 |
| POST | `/Admin/User/Mfa/Totp/Start` | 登录用户 | 返回 secret + otpauth URI |
| POST | `/Admin/User/Mfa/Totp/Confirm` | 登录用户 | 确认首码并启用 |
| POST | `/Admin/User/Mfa/Channel` | 登录用户 | 启停 sms/mail 通道 |
| POST | `/Admin/User/Mfa/Disable` | 登录用户 | 关闭 MFA（需验证） |
| POST | `/Admin/User/Mfa/BackupCodes` | 登录用户 | 重新生成恢复码 |

## 5. 安全要点

- TOTP 密钥与恢复码哈希不可明文回显（绑定确认后仅展示一次明文恢复码）
- `mfaToken` 短期、单用途倾向（成功后作废）；绑定用户与挑战用户必须一致
- 挑战失败计入登录失败次数（与现有 `MaxLoginError` 联动）
- SMS/Mail 发送沿用现有频控与 `VerifyCodeRecord`

## 6. 测试要点

- EnableMfa 关/开矩阵
- 仅 TOTP / 仅 SMS / 多通道切换
- 恢复码一次有效、错误码不消耗
- MfaRequired 未绑定路径
- API 与 MVC 表单两条路径
